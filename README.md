# CinaCina

beatoraja用の進捗管理ツール。公開URLを開き、各自のDBをブラウザー内だけで読み取り・保存します。アカウントや記録用サーバーは不要です。

## 起動

このフォルダーで `npm start` を実行し、ブラウザーで http://127.0.0.1:4318 を開きます。終了は起動したターミナルで Ctrl+C。

公開版の利用にNode.jsは不要です。ローカル開発・テストはNode.js 24以上を使用します。`dist/` はそのまま静的ホスティング（GitHub Pages等）に配置できます。WASMと画像を含め、すべて相対パスです。

## GitHub Pagesへの公開

GitHubリポジトリへコードをpushし、Settings → Pages → Build and deploymentのSourceを「GitHub Actions」に設定します。同梱の `.github/workflows/pages.yml` がmain更新時に `dist/` だけを公開します。初回はActions画面から手動実行もできます。個人データの `data/` と `config.local.json` はGit管理・公開対象に含めません。

公開URLが変わるとブラウザーの保存領域も別になります。以前のURLでバックアップを書き出し、新しいURLで復元してください。

## 保存とバックアップ

記録と調子はIndexedDBに保存し、再アクセス時に復元します。保存先はブラウザー・プロファイル・サイトのURL単位です。別PCとの自動同期はありません。プライベートブラウズやサイトデータ削除では消えることがあります。

画面下部の「バックアップを保存」でJSONを書き出し、「バックアップを復元」で移行できます。復元は内容確認後に現在の記録を置き換えます。旧版の `data/state.json` も復元できます。元のDBは変更せず、選択したDBや個人の集計結果を外部へ送信しません。

## 使い方

1. プレイ終了後に「プレイ記録を取り込む」を押します。
2. プレイヤーフォルダーのscore.db / scorelog.dbを選びます。初回は本体フォルダーのsongdata.dbも推奨します（任意）。表外の曲名とMD5→SHA256照合に使う情報だけを保存するので、次回以降は2ファイルで更新できます。新たに追加した譜面が未照合ならsongdata.dbをもう一度選んでください。
3. 追加・更新されたプレイ日について、神格Ｂ・Ｂ・デスＢから調子を選びます。初回は最新プレイ日だけを案内します。過去の日も後から編集できます。
4. カレンダーでプレイ日を選択すると、日別の打鍵数・ランプ更新を表示します。
   難易度表のグラフの色付き部分をクリックすると、そのレベル・ランプの曲一覧が開きます。12曲ずつのページ切替、曲名検索、難易度・ランプ切替に対応します。難易度名からは全曲一覧を開けます。旧データは一度DBを再取り込みすると一覧が利用できます（調子は保持）。
5. 日別詳細の「投稿用テキストをコピー」で、EC / C / HC / EXHC / FC別の投稿文を表示・編集・コピーできます。該当曲のない区分とNP→Fは含めません。難易度表記と曲の並び順は日別一覧に従います。Twitterへの投稿は貼り付けて行ってください。

取り込みはWeb Workerと同梱のsql.js/WASMで処理します。保存の完了後に表示を更新し、失敗時には前の記録を残します。

## 集計仕様

- 打鍵数はbeatoraja `IntegerPropertyFactory.player_notes`（333）と同じ、PGREAT/GREAT/GOOD/BADのFAST+SLOW合計。日別の累積値の差分を使用します。空打ち・見逃しは含めません。
- 日本時間の日付で表示。日付はbeatorajaの記録に従います。一曲の途中で0時を超えた場合、その曲を秒単位で分割する機能ではありません。
- 再取り込みは最新スナップショットへの置き換えで、二重加算しません。記録が減る古いDBは拒否します。
- 同日同譜面の複数更新は、その日の最初の状態→最後の状態にまとめます。NP→Fも状態更新として表示します。
- 日別のランプ更新グループは★★、★、st、slの順、各表内は数値レベル降順、同レベルは曲名順。複数表の譜面はこの優先順で1グループにだけ表示します。対象4表のいずれにも照合できない譜面は表外として末尾。投稿用テキストも各「新規ランプ」区分の中を同じルールで難易度別にまとめます。
- 初版は通常LNモード（DB mode=0）のランプを使用します。PERFECT/MAXはFCに集約。ASSIST系は誤ったランプに変換せず「補助」と表示します。
- 難易度表はdist/catalog.jsonに同梱した公開表のスナップショットです（取得元URLは各表のurlに記録）。自動更新ではありません。SHA256のない表は任意のsongdata.dbで照合します。songdata.db未選択時は一部が未照合・NPになります。
- 0打鍵日は日付だけ表示します。調子は未登録を許容し、最後の選択で上書きします。
- 調子アイコンはimages/GOD_B.png（神格Ｂ）、B.png（Ｂ）、DEATH_B.png（デスＢ）を表示します。

## 検証

`npm test`：日付境界、打鍵集計、クリアID変換、難易度ソート、重複取り込み、同日の増分、古いDBの拒否。

`npm run check`：JavaScript構文チェック。

`npm ci`でsql.jsを準備し、`npm test`でWASMによるDB解析・バックアップ検証も実行します。

`scripts/prepare-browser.mjs`は開発者向けです。config.local.jsonのbeatorajaPathから対象4表の公開メタデータだけを抽出し、sql.jsと画像をdistへコピーします。個人のscore/scorelog/songdataやdata/を公開先へコピーしないでください。旧版との実データ比較は`node scripts/verify-local.mjs`で実施でき、移行用バックアップは非公開のdata/に出力します。
